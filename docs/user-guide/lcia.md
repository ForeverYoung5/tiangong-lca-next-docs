# LCIA 计算与结果查看

本页说明 TianGong LCA 中两类常见的 LCIA（生命周期影响评价）使用方式：

- 在**过程**或**模型**详情中直接查看 LCIA 结果
- 在需要跨过程比较、分组或贡献路径分析时，转到
  [过程分析工作区](./process-analysis)

## LCIA 是什么

LCIA 会把 LCI（生命周期清单）结果转换为环境影响类别结果，例如气候变化、酸化、臭氧消耗
等指标。

平台当前既支持：

- **过程层级**的 LCIA 结果查看
- **模型层级**的 LCIA 结果查看

这两种方式都适合快速核对结果；如果要做批量比较或路径追踪，请使用单独的分析工作区。

## 使用前准备

建议在运行 LCIA 前先确认：

- 过程或模型已经完成必要的输入 / 输出建模
- 已正确设置参考流或功能单位
- 尽量复用平台提供的标准流属性、单位组和基础流
- 相关影响方法中确实存在可匹配的表征因子
- 用于模型或贡献路径求解的产品输入交换，已经设置合适的交换项地区；如果留空，系统会使用消费
  过程自身的地区作为默认供给地区
- provider 过程的年度供应或产量字段已经按数值录入，因为它会影响同一地区内多个 provider 的
  分摊比例

如果您大量使用自定义单位组、流属性或非标准基础流，可能会出现无法计算、结果缺失或量级
异常的问题。

## 过程层级 LCIA

### 过程层级入口

在**我的数据 → 过程**中打开目标过程后，可以在过程编辑或查看结果区域中进入 LCIA 结果。

![LCIA 结果面板](./img/lcia-calculation.png)

### 过程层级适用场景

- 快速检查某一个过程的环境影响画像
- 判断某些影响类别是否存在明显异常
- 在建模阶段做单过程自检

### 结果特点

过程层级的 LCIA 结果主要反映该过程涉及的基础流环境影响。

请注意：

- 它适合查看**单个过程本身**
- 它不等同于完整产品系统的总影响
- 它不适合替代跨过程比较、分组统计或贡献路径分析

## 模型层级 LCIA

### 模型层级入口

在**我的数据 → 模型**中打开目标模型后，可在模型结果区域运行或查看 LCIA 结果。

### 模型层级适用场景

- 查看完整产品系统或模型网络的影响结果
- 对比多个建模方案的整体差异
- 在正式分析前确认模型求解是否合理

### 与过程层级的区别

| 场景 | 更适合的入口 |
| --- | --- |
| 检查单个过程 | 过程层级 LCIA |
| 检查完整系统结果 | 模型层级 LCIA |
| 比较多个过程 | [过程分析工作区](./process-analysis) |
| 做贡献路径追踪 | [过程分析工作区](./process-analysis) |

## 什么时候转到“过程分析工作区”

如果您的目标是下面这些更高级的分析任务，请不要只停留在 LCIA 结果面板：

- 对多个过程做**影响比较**
- 按**地区、分类、数据集类型、团队**做分组统计
- 查看某个根过程的**贡献路径**
- 在**当前用户数据 / 开放数据 / 全部分析范围**之间切换

此时应直接使用 [过程分析工作区](./process-analysis)。

## 常见问题排查

### 为什么结果缺失或只有部分影响类别？

优先检查：

- 流是否绑定了正确的标准流属性
- 单位组是否可正确换算
- 所选影响方法是否包含对应表征因子

### 为什么结果量级明显异常？

常见原因包括：

- 单位换算错误
- 自定义单位组或流属性与平台标准不兼容
- 参考流或功能单位设置不合理

### 为什么我更需要“过程分析工作区”？

如果您已经不满足于查看单个结果，而是需要比较、汇总、分层或追踪来源，就应该转到
[过程分析工作区](./process-analysis) 继续操作。
