# 过程分析工作区

TianGong LCA 现在提供了一个独立的**过程分析工作区**，用于在多个过程之间进行 LCIA 相关的
高级分析。

它与普通的 [LCIA 计算与结果查看](./lcia) 不同：

- `LCIA` 页面更适合查看单个过程或单个模型的结果
- 本页介绍的工作区更适合跨过程比较、分组和路径追踪

## 从哪里进入

当前入口位于：

1. 打开**我的数据 → 过程**
2. 在过程列表页工具栏中点击 **LCA Analysis**

该页面属于工作区内的高级入口，不一定直接出现在左侧导航菜单中。

## 公共输入区

进入分析页后，页面顶部会先要求您设置分析输入。所有分析标签都共享两组核心条件：

- **数据范围**
- **过程搜索**

### 数据范围

当前可选范围包括：

- **当前用户数据**
- **开放数据**
- **全部数据**

建议按分析目标选择：

- 只想检查个人草稿时，用**当前用户数据**
- 想基于已发布数据做比较时，用**开放数据**
- 想扩大候选范围时，再使用**全部数据**

### 过程搜索

过程搜索用于缩小候选过程数量。搜索条件会直接影响后续各标签页中的可选过程列表。

## 过程数据对分析结果的影响

过程分析依赖过程网络快照。构建快照时，平台会优先使用输入交换项中的 `location` 作为供应地区
锚点；如果该字段缺失或不可用，再回退到消费过程自身的位置。

当一个输入流可以连接到多个候选供应过程时，平台会先按供应地区筛选候选项，再在同一地区层级内
使用候选过程的年供应量或年产量作为权重。年供应量缺失、无法解析或不大于零时，该候选过程会按
默认权重 `1.0` 参与分配。

为了让分析结果更可解释，建议在维护过程数据时：

- 在输入交换项中选择标准 ILCD 地理位置代码
- 为过程填写可解析的年供应量或年产量
- 保持参考流、单位和流属性与平台标准配置一致

## 标签一：过程画像

**过程画像**适合查看一个过程的 LCIA 影响轮廓。

### 过程画像的操作方式

1. 选择一个过程
2. 点击 **Load profile**

### 过程画像的结果内容

结果区域通常包括：

- 查询元信息，如 `snapshot_id`、`result_id`、来源、计算时间
- 当前选中过程的摘要
- **Non-zero categories** 统计
- **Normalized profile chart**
- 下方的影响类别明细表

如果您只想快速了解某个过程在各影响类别上的相对强弱，这个标签通常已经足够。

## 标签二：影响比较

**影响比较**用于在同一个影响类别下比较多个过程。

### 影响比较的操作方式

1. 选择一个**影响类别**
2. 在过程选择区勾选多个过程
3. 点击 **Run analysis**

如需重选，可先点击 **Clear selection**。

### 影响比较的结果内容

该标签通常会给出：

- 比较过程数量
- 最高贡献项
- 绝对总量
- 比较图表
- 过程明细表

当您要比较多个候选过程哪一个环境影响更高时，应优先使用此标签。

## 标签三：分组结果

**分组结果**适合把多个过程按某种维度汇总后再比较。

### 可选分组维度

当前界面支持的分组方式包括：

- **地区**
- **分类**
- **数据集类型**
- **团队**

### 分组结果的操作方式

1. 选择一个**影响类别**
2. 选择一个 **Group by** 维度
3. 勾选多个过程
4. 点击 **Run grouped analysis**

### 分组结果的结果内容

结果通常包括：

- 分组数量
- 选中过程数量
- 最高贡献组
- 绝对总量
- **Grouped ranking chart**
- 分组明细表

这个标签适合回答“哪一类过程总体影响最大”之类的问题。

## 标签四：贡献路径

**贡献路径**用于从一个根过程出发，追踪影响沿过程网络展开的主要路径。

### 输入项

除了影响类别和根过程外，页面还支持调整以下参数：

- **Amount**
- **Max depth**
- **Top-k children**
- **Cutoff share**
- **Max nodes**

### 贡献路径的操作方式

1. 选择一个**影响类别**
2. 通过单选方式指定一个**根过程**
3. 根据需要调整参数
4. 点击 **Run contribution path**

### 贡献路径的结果内容

结果区域通常包括：

- 总影响
- 覆盖率
- 展开节点数
- 截断节点数
- 根过程与参数回显
- 直接贡献者图表
- **Contribution path Sankey**
- 下方的分支、节点或连接明细表

如果您的目标是理解“某个影响主要是沿哪些上游路径传递出来的”，应优先使用这一标签。

## 与任务中心的关系

部分分析任务会触发后台求解。出现等待时，请留意顶部的
[TIDAS ZIP 导入、导出与任务中心](./tidas-zip-workflows) 中介绍的**任务中心**提示。

## 什么时候不用这个工作区

以下场景通常不必进入过程分析工作区：

- 只看单个过程或单个模型的 LCIA 结果
- 只需要导出普通 JSON
- 只需要做数据审核或权限管理

这些需求分别更适合：

- [LCIA 计算与结果查看](./lcia)
- [数据审核](./data-review)
- [权限与数据空间矩阵](./permissions-and-data-scopes)
